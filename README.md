# GPU-Accelerated Network Flow Feature Extraction

Final project for CIIC 5019 High-Performance Computing, University of Puerto Rico at Mayagüez.
Author: Johnel Cunningham Rivera.

The programs turn a batch of captured packets into flow records. A flow is the set of
packets with the same source address, destination address, source port, destination port
and protocol. For every flow, 25 features are computed: packet and byte counts, rates,
duration, packet-length statistics, inter-arrival-time statistics, TCP flag counts, the
entropy of the packet-length histogram, and burst characteristics.

The same result is produced by six implementations:

| Name | Model | Idea |
|---|---|---|
| `seq` | one thread | hash table updated packet by packet (reference) |
| `omp-merge` | OpenMP | one private table per thread over a time chunk, then an associative merge |
| `omp-part` | OpenMP | partition packets by flow hash, one private table per partition |
| `gpu-flow` | CUDA | lock-free hash table, stable sort, one thread per flow |
| `gpu-atomic` | CUDA | same grouping, one thread per packet with atomic updates |
| `gpu-chunk` | CUDA | same grouping, one thread per chunk of sorted packets |

An MPI4Py driver distributes batches of capture files among processes.
The report is in [`report/report.pdf`](report/report.pdf).

## Layout

```
code/
  src/common.h            packet and flow record, feature formulas (shared by CPU and GPU)
  src/flowfeat.h          host interface, hash table, buffer pool
  src/cpu.cpp             sequential baseline and the two OpenMP strategies
  src/gpu.cu              CUDA pipeline
  src/util.cpp            synthetic generator, .pkt files, checksums and comparisons
  src/main.cpp            flowfeat command-line program
  src/pcap2pkt.cpp        converts a pcap capture into .pkt batches
  src/contention_bench.cpp  micro-benchmark of a shared table (locks, atomics)
  src/capi.cpp            C interface used from Python
  python/mpi_flows.py     MPI4Py driver for batches
  python/flowlib.py       ctypes binding of libflowfeat.so
  python/ref_python.py    independent plain-Python reference
  python/verify.py        correctness tests
  python/run_benchmarks.py, make_plots.py, plot_style.py
  configs/*.json          experiment matrices
  scripts/run_on_gpu_host.sh
results/<machine>/        raw results (JSON lines), environment, logs, test output
results/summary.csv       medians of every configuration
report/                   LaTeX sources, generated figures and tables, report.pdf
```

## Requirements

- A C++17 compiler with OpenMP (GCC; on macOS `brew install gcc`, the Makefile uses `g++-16`).
- Optional: an NVIDIA GPU with the CUDA toolkit (`nvcc`, Thrust). Tested with CUDA 12.0 on a
  Quadro P2000 (`ARCH=sm_61`, host compiler `g++-12`). For another GPU: `make CUDA=1 ARCH=sm_75`.
- Optional: Open MPI and Python 3 with `numpy`, `mpi4py`, `matplotlib`.

```bash
python3 -m venv .venv && .venv/bin/pip install numpy mpi4py matplotlib
```

## Build

```bash
cd code
make            # CPU only
make CUDA=1     # with the CUDA implementations
```

## Run

```bash
./flowfeat                                                    # demonstration: 2^20 synthetic packets, sequential
./flowfeat --impl omp-part --threads 8 --logn 24 --zipf 1.0 --check
./flowfeat --impl gpu-chunk --logn 24 --zipf 1.5 --check --warmup 1 --reps 5
./flowfeat --impl seq --input ../data/mawi_60s.pkt --out flows.csv
./flowfeat --help
```

`--check` compares the result with the sequential reference. `--out` writes one row per
flow with all the features.

Batches with MPI4Py:

```bash
mpirun -n 4 ../.venv/bin/python python/mpi_flows.py ../data/w30/*.pkt --schedule dynamic
```

## Data

Synthetic traffic is generated by the programs (`--logn`, `--flows`, `--zipf`, `--seed`).

The real trace is a public 15-minute backbone capture from the MAWI Working Group Traffic
Archive (sample point F, 2024-01-01 14:00, 3.6 GB compressed). Download and convert it:

```bash
mkdir -p data/w30 && cd data
curl -LO https://mawi.wide.ad.jp/mawi/samplepoint-F/2024/202401011400.pcap.gz
gunzip -c 202401011400.pcap.gz | ../code/pcap2pkt - w30/mawi --window 30      # 30-second batches
rm w30/mawi_0030.pkt                                                          # 255 packets after the last full window
for s in 60 120 240; do gunzip -c 202401011400.pcap.gz | ../code/pcap2pkt - mawi_${s}s --max-seconds $s; done
```

`pcap2pkt` reads classic pcap files (Ethernet, Linux cooked or raw IP link types) and keeps
IPv4 packets. Please follow the MAWI archive's terms of use when using the trace.

## Tests

```bash
cd code
../.venv/bin/python python/verify.py --pkt ../data/mawi_60s.pkt
```

The sequential program is compared with an independent plain-Python implementation, and
every parallel implementation is compared with the sequential one. Integer accumulators
must be identical; derived features must agree to a relative tolerance of 1e-9. The saved
outputs are in `results/*/verify_output.txt`.

## Reproduce the experiments

```bash
cd code
../.venv/bin/python python/run_benchmarks.py --config configs/media_vm.json --out ../results/media_vm   # GPU machine, about 40 minutes
../.venv/bin/python python/run_benchmarks.py --config configs/mac_m4.json --out ../results/mac_m4       # CPU only, about 4 minutes
../.venv/bin/python python/make_plots.py                                                                 # figures, tables, summary.csv
cd ../report && tectonic report.tex
```

`scripts/run_on_gpu_host.sh` is the wrapper used on the GPU machine; it pauses two media
services that share that GPU and restarts them afterwards. On another machine call
`run_benchmarks.py` directly. The configuration files list every experiment; edit thread
counts and sizes there to match your hardware.
